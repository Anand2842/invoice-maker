# Release checkpoint — 7 November 2026 (P0/P1 completion branch `p0-p1-completion`)

Builds on `RELEASE-2026-11-03.md`; everything said there about Vercel and separate Supabase activation still applies.
External providers remain mocked (email, GSP/IRP, e-Way Bill, payment gateway). Nothing in this release files a
return, generates a legal IRN, charges a card or sends real email until real provider credentials are configured.

## New migrations (apply after the 3 November list, in this order)

1. `202611070001_revoke_anon_access_helpers.sql`: `anon` can no longer execute `billing_can_access` or
   `billing_is_owner`. Every policy using them is `to authenticated`.
2. `202611070002_receipt_obligation_guard.sql`: direct receipts can no longer overpay an invoice outside the cash
   workspace (found by the real-Postgres race test).
3. `202611070101_einvoice_ewaybill.sql`: IRN and e-Way Bill records through a mock GSP (`docs/EINVOICE-EWAYBILL.md`).
4. `202611070201_gstr2b_reconciliation.sql`: GSTR-2B import snapshots and reviewed reconciliation decisions
   (`docs/GST-PORTAL-RETURNS.md`).
5. `202611070401_tds.sql`: TDS on vendor bills, challans, customer receipts and the 26Q export (`docs/TDS.md`).
   It replaces `billing_settlement_movements` so vendor TDS reduces net payable.
6. `202611070501_automation_gateway.sql`: payment reminders, recurring drafts, email outbox and online payment
   links/webhooks (`docs/AUTOMATION-PAYMENTS.md`).
7. `202611070601_audit_trail.sql`: read-only audit trail across records, ledger, bank, inventory and team
   (`/audit/`). Team changes are visible to the owner only.

No migration is needed for CSV import of clients, vendors and items (`/import/`). It writes through the existing
records table under RLS.

No new migration needs pgcrypto. HMAC and hashing use built-in `sha256()`.

## Independent review fixes (Codex review of this branch, all 15 findings addressed before first apply)

These migrations had never been applied anywhere, so the fixes are made in the migration files themselves.

* **Recurring automation:** each run takes at most 25 due subscriptions per business, interleaved. A failed
  subscription backs off 1, 2, 3… up to 7 days (`billing_automation_failed`) and is listed on `/automation/`.
* **Gateway:**
  * Real (Razorpay) links are INR only. They return a Reference ID to set on the Razorpay payment link instead
    of a Folio pay URL that could not take payment.
  * Receipts are dated on the provider capture day.
  * A capture that cannot be posted (for example in a closed period) is kept as `needs-review`, not lost.
  * Retrying the same gateway configuration command now replays instead of failing.
* **Email outbox:**
  * A sender must quote the claimed attempt number, so an expired worker cannot overwrite a newer lease.
  * Reminders are cancelled at delivery if reminders were turned off or the invoice was settled.
  * Reminders are re-worded if a part payment changed the balance.
  * Outstanding balances ignore future-dated receipts.
* **TDS:**
  * 194Q deducts only on this year's purchases from the seller above ₹50 lakh, counting earlier bills issued
    without TDS.
  * The same challan (BSR, date, serial) cannot be posted twice unless the first is reversed.
* **Receipts:** legacy-invoice receipts are checked against the dated running balance, so a later reversal cannot
  license an earlier-dated overpayment.
* **e-Way Bill (simulated):** validity now ends at midnight of the last day, one day later than before.
* **CSV import:** a partially failed import shows the error and keeps the file for retry.
* **Rehearsal script:** parses the connection URL and refuses any non-loopback host.

The rehearsal proves the migrations against an emulated Supabase. It is not the production audit: run the same
scripts against a **staging copy of production** before applying anything there.
