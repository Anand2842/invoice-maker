# Release checkpoint — 7 November 2026 (P0/P1 completion branch `p0-p1-completion`)

Builds on `RELEASE-2026-11-03.md`; everything said there about Vercel and separate Supabase activation still applies.
External providers remain mocked (email, GSP/IRP, e-Way Bill, payment gateway). Nothing in this release files a
return, generates a legal IRN, charges a card or sends real email until real provider credentials are configured.

## New migrations (apply after the 3 November list, in this order)

1. `202611070001_revoke_anon_access_helpers.sql`: `anon` can no longer execute `billing_can_access` or
   `billing_is_owner`. Every policy using them is `to authenticated`.
2. `202611070002_receipt_obligation_guard.sql`: direct receipts can no longer overpay an invoice outside the cash
   workspace (found by the real-Postgres race test).
3. `202611070101_einvoice_ewaybill.sql`: IRN and e-Way Bill records through a mock GSP (`docs/EINVOICE-EWAYBILL.md`).
4. `202611070201_gstr2b_reconciliation.sql`: GSTR-2B import snapshots and reviewed reconciliation decisions
   (`docs/GST-PORTAL-RETURNS.md`).
5. `202611070401_tds.sql`: TDS on vendor bills, challans, customer receipts and the 26Q export (`docs/TDS.md`).
   It replaces `billing_settlement_movements` so vendor TDS reduces net payable.
6. `202611070501_automation_gateway.sql`: payment reminders, recurring drafts, email outbox and online payment
   links/webhooks (`docs/AUTOMATION-PAYMENTS.md`).

No new migration needs pgcrypto. HMAC and hashing use built-in `sha256()`.

## Rehearsal evidence (local, PostgreSQL 17.11 in Docker, Supabase roles, auth and default privileges emulated)

* `PGREHEARSAL_URL=postgres://postgres@127.0.0.1:55432/postgres node scripts/pg-rehearsal.mjs fresh`
  * All 44 migrations apply.
  * The audit finds every public table under RLS, every definer with a fixed `search_path`, no `anon` table
    writes, and no `anon`-executable definer outside the intended gated entry points (`ANON_ENTRY_POINTS`).
* `… pg-rehearsal.mjs upgrade`
  * Schema at the confirmed production baseline `202610300002`, seeded with legacy clients, invoices, items,
    expenses, vendors and leads.
  * Applies the 32 later migrations.
  * Legacy rows stay byte-identical, members still read them, and outsiders read none.
* `… pg-race-tests.mjs`, real overlapping connections behind a held lock:
  * Six payments against one invoice cannot overpay.
  * Six retries of one command make one payment.
  * Ten concurrent document numbers are distinct.
  * Five dispatches of the last stock unit post one.
  * An editor removed while queued cannot write.

The rehearsal proves the migrations against an emulated Supabase. It is not the production audit: run the same
scripts against a **staging copy of production** before applying anything there.
