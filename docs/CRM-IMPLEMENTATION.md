# CRM implementation and verification — 3 November 2026

This source is unpublished and its additive migration is not applied to staging or production. Last confirmed hosted release remains private v14. T29 is not marked Done: hosted/browser/mobile-web and actual overlapping-connection proof remain pending.

`202611020002_crm_commands.sql` adds versioned pipelines/stages, typed lead ownership and explicit capabilities, assigned dated tasks, planned meetings and logged communications, private retained originals, exact reviewed dedup/merge, client linkage and quotation drafts. Every command records an immutable event, exact actor/request retry result and transactional outbox. Business lock precedes authorization recheck and typed lead locks; explicit legacy adoption retains the existing source-record → business lock order. No generic record is automatically imported or merged by name.

`/crm/`, `/api/crm` and `/api/crm/files` expose actual SQL-backed workflows. Owner/admin or reviewed CRM managers manage routing/pipelines; writers create/work their allowed leads and task assignees may complete assigned follow-ups. Viewer capability grants cannot bypass business write restrictions. Exact normalized email/phone candidates require explicit ownership review before retaining another lead. Merges retain aliases, original tasks, files, quotations and events on their original IDs. Adoption freezes the original generic lead record without changing its data. New client matching uses an exact saved ID or explicit reviewed creation, never names.

Quotation draft creation preserves `sourceRecord`, `crmLeadId`, `crmCanonicalLeadId`, `crmLeadVersion`, `crmPipelineId` and optional `clientId`. Original quotation provenance is immutable; quotation → invoice retains the CRM IDs and correctly links the quotation as its immediate source. The editor and clone metadata work is integrated by the root agent. Draft quotations are counted as drafts, not sales.

Dated list/detail/report reads capture transactional CRM sequence ceilings. Search uses the frozen lead-event search vector, so a later edit cannot change captured-page membership. Current permissions remain authoritative; historical detail and current lead version are returned separately. Keyset cursors are rejected outside their dated filtered list or lead-family timeline. Opportunity currency groups remain separate; source/team/pipeline conversion counts retain merged/archived provenance. Task summary is all visible tasks at the selected date and snapshot, independent of lead search filters. CSV exports label complete report groups versus the current lead page.

Private uploads use the actual `billing-files` bucket with the user's JWT and deterministic non-upsert paths under business/crm/lead. Retrying an existing upload verifies the same bytes before returning its metadata. Restrictive SELECT/INSERT/UPDATE/DELETE storage policies constrain the existing permissive business policies; existing non-CRM paths retain prior authorization. Attached CRM originals cannot be overwritten or deleted through generic storage access. SQL accepts recorded MIME/size/SHA claims only after checking a matching private object exists; the recorded fingerprint is explicitly not an independent verification of stored content. A failed metadata command may leave an unattached private upload; no automatic destructive cleanup is attempted.

UI saves exact commands in account/business/data-mode session storage before sending. Ambiguous requests retain their key across later failures; initial definite rejections permit reviewed correction. Logged email/WhatsApp interactions do not send anything. Calendar invitations, public forms and external routing are not supplied by T29.
